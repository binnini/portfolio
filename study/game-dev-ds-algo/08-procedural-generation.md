## 0. 대전제: 시드 기반 결정론

```csharp
var rng = new System.Random(seed);   // UnityEngine.Random(전역 상태) 대신
```

- 시드 공유는 그 자체로 콘텐츠가 됨 (마인크래프트 시드 공유 문화)

## 1. 노이즈

### 펄린 / 심플렉스 노이즈
격자점마다 랜덤 그래디언트를 두고 보간해 **연속적이고 자연스러운** 난수 필드를 만듭니다.

```csharp
// fBm (Fractal Brownian Motion): 옥타브를 겹쳐 디테일 추가
float FBM(float x, float y, int octaves) {
    float sum = 0f, amp = 1f, freq = 1f, norm = 0f;
    for (int i = 0; i < octaves; i++) {
        sum  += Mathf.PerlinNoise(x * freq, y * freq) * amp;
        norm += amp;
        amp  *= 0.5f;   // persistence
        freq *= 2f;     // lacunarity
    }
    return sum / norm;
}
```

| 파라미터 | 효과 |
|---|---|
| frequency | 지형의 규모 (낮으면 완만한 대륙, 높으면 잔잔한 요철) |
| octaves | 디테일 레벨 수 |
| persistence | 옥타브마다 진폭 감소율 (거칠기) |
| lacunarity | 옥타브마다 주파수 증가율 |

### 사용처
- 지형 높이맵, 바이옴 분포(온도/습도 노이즈 2장을 조합)
- 구름, 안개, 물결, 불꽃
- 텍스처 생성 (대리석, 나무결)
- 동굴 생성 (3D 노이즈 임계값)
- 자원 광맥 분포

### 기타 노이즈
- **Worley / Voronoi 노이즈** — 세포 패턴. 돌바닥, 갈라진 땅, 영역 분할, 바이옴 경계
- **White noise** — 단순 랜덤. 연속성이 없어 지형엔 부적합
- **Domain warping** — 노이즈 입력 좌표를 다른 노이즈로 왜곡. 훨씬 유기적인 형태

## 2. 셀룰러 오토마타 (동굴 생성)

가장 구현이 쉬우면서 결과가 좋은 기법입니다.

```
1. 맵을 랜덤 채움 (벽 확률 약 45%)
2. 다음 규칙을 4~6회 반복:
     이웃 8칸 중 벽이 5개 이상 → 나도 벽
     아니면                    → 빈 칸
3. 결과: 자연스러운 동굴 형태
4. 플러드 필로 고립된 작은 영역 제거 또는 통로 연결
```

```csharp
int[,] Step(int[,] map, int w, int h) {
    var next = new int[w, h];
    for (int x = 0; x < w; x++)
    for (int y = 0; y < h; y++) {
        int walls = CountWallNeighbors(map, x, y);   // 맵 밖은 벽으로 취급
        next[x, y] = walls > 4 ? 1 : (walls < 4 ? 0 : map[x, y]);
    }
    return next;
}
```

### 사용처
동굴형 던전, 섬 형태, 광물 분포, 파괴 가능 지형

## 3. BSP 던전 생성

```
1. 맵 전체를 하나의 사각 영역으로 시작
2. 재귀적으로 가로 또는 세로로 랜덤 분할 (최소 크기 도달 시 중단)
3. 각 리프 영역 안에 여유를 두고 방을 배치
4. 형제 리프의 방 중심끼리 L자 통로 연결 → 위로 올라가며 반복
```

### 특징
- 방이 겹치지 않음이 **구조적으로 보장**
- 격자형 인공 던전 느낌 (로그라이크 클래식)
- 방 크기/분할 비율로 분위기 조절 가능

### 변형: 방 배치 + 들로네 + MST
```
1. 랜덤 위치/크기의 방을 뿌리고 물리적으로 밀어내 겹침 해소
2. 방 중심들로 들로네 삼각분할
3. MST를 뽑아 최소 연결 확보 (04번 문서 — 유니온 파인드)
4. MST에서 빠진 간선 중 10~15%를 랜덤 복원 → 루프 생성
```
MST만 쓰면 트리 구조라 막다른 길만 반복돼 지루합니다. **루프 복원이 재미의 핵심**입니다.

## 4. 재귀 백트래킹 미로

```
1. 시작 칸을 방문 표시하고 스택에 push
2. 현재 칸의 미방문 이웃 중 하나를 랜덤 선택
3. 벽을 허물고 그 칸으로 이동, push
4. 미방문 이웃이 없으면 pop (백트래킹)
5. 스택이 빌 때까지 반복
```
긴 복도 위주의 "구불구불한" 미로가 나옵니다. Prim/Kruskal 방식은 더 분기가 많은 미로를 만듭니다.

## 5. 웨이브 함수 붕괴 (WFC)

타일 간 **인접 규칙**만 주면 규칙을 만족하는 배치를 생성합니다. 제약 전파 + 백트래킹.

```
1. 모든 셀이 "모든 타일 가능" 상태로 시작 (중첩 상태)
2. 엔트로피가 가장 낮은(가능성이 가장 적은) 셀을 선택
3. 그 셀을 가중치 랜덤으로 하나의 타일로 확정 (붕괴)
4. 인접 규칙에 따라 이웃의 가능 목록을 제거 → 연쇄 전파
5. 모순 발생 시 백트래킹 또는 재시작
6. 모든 셀이 확정될 때까지 반복
```

### 사용처
- 타일 기반 맵 자동 생성 (예시 이미지 한 장에서 규칙을 학습해 무한 변주)
- 도시/마을 배치, 던전 방 조합
- 텍스처 합성

### 주의점
- 모순 발생률이 높으면 무한 재시작 → 규칙 설계와 백트래킹 전략이 중요
- 큰 맵은 청크 단위로 나눠 생성

## 6. 포아송 디스크 샘플링

**최소 거리 r 이상 떨어진** 점들을 고르게 흩뿌립니다. 순수 랜덤은 뭉치고 비는 구간이 생깁니다.

```
순수 랜덤:   ● ●●●    ●        ●●      ← 뭉침과 공백
포아송:      ●   ●   ●   ●   ●   ●     ← 고르되 규칙적이지 않음
```

### 사용처
- 나무/풀/바위 배치 (자연스러운 식생)
- 적 스폰 포인트, 아이템 배치
- 파티클 초기 분포
- 샘플링 기반 렌더링(SSAO 커널, 소프트 섀도우)

Bridson 알고리즘이 O(n)으로 널리 쓰입니다.

## 7. 셔플과 랜덤 선택

### 피셔-예이츠 셔플 (편향 없는 O(n) 셔플)
```csharp
for (int i = list.Count - 1; i > 0; i--) {
    int j = rng.Next(i + 1);        // 0..i 에서 선택 (0..n-1 아님! 흔한 버그)
    (list[i], list[j]) = (list[j], list[i]);
}
```
- 사용처: 카드 덱 셔플, 랜덤 순서 스폰, 퀴즈 문제 순서

### 가중치 랜덤 — 누적 분포 + 이진 탐색
```
드롭 가중치: 일반 70, 희귀 25, 전설 5
누적 배열  : [70, 95, 100]
rand(0,100) = 91 → 이진 탐색 → 인덱스 1 → 희귀
```
- 사용처: 드롭 테이블, 가챠, 몬스터 스폰 종류 선택
- 가중치가 고정이면 누적 배열을 미리 만들어두고 O(log n)

### Alias Method
전처리 O(n) 후 **샘플링 O(1)**. 가챠처럼 같은 분포로 수만 번 뽑을 때 유리합니다.

### 체감 공정성 보정 (게임 디자인 알고리즘)
순수 확률은 "10번 연속 꽝"을 만들어 유저가 조작을 의심합니다.
| 기법 | 설명 |
|---|---|
| **천장 (Pity)** | n회 실패 시 확정 지급 |
| **점증 확률** | 실패할수록 확률 상승 (Dota2의 PRD — Pseudo Random Distribution) |
| **주머니 방식 (Bag)** | 결과를 통에 넣고 섞어 꺼냄. 테트리스 7-bag이 대표적 — 같은 블록 연속을 구조적으로 차단 |
| **가중치 감쇠** | 최근 나온 것의 가중치를 일시적으로 낮춤 |

## 8. 마칭 큐브 / 마칭 스퀘어

스칼라 필드(밀도값)를 임계값 기준으로 잘라 **메시(2D는 선)** 를 생성.

### 사용처
- 복셀 지형의 부드러운 표면 (마인크래프트의 각진 형태와 대비)
- 메타볼, 액체/슬라임 표면
- 셀룰러 오토마타 동굴의 격자 벽을 부드러운 윤곽선으로 변환 (마칭 스퀘어)
- 의료 영상 등 볼륨 렌더링

## 9. 생성 후 검증 — 빠뜨리면 안 되는 단계

절차적 생성은 **"생성"보다 "검증"이 실무 난이도**입니다.

- [ ] 시작점에서 출구까지 도달 가능한가? → **BFS / 플러드 필**
- [ ] 고립된 영역이 있는가? → **플러드 필 / 유니온 파인드**
- [ ] 필수 아이템(열쇠)이 잠긴 문 뒤에 있는가? → **위상 정렬 / 도달성 검사**
- [ ] 방 개수·난이도·보상 총량이 기준 범위인가? → 통계 검증
- [ ] 실패 시 재생성 vs 보정? → 재생성 횟수 상한 필요

검증에 실패하면 시드를 바꿔 재생성하거나, 통로를 강제로 뚫는 보정을 넣습니다.

## 체크리스트

- [ ] 왜 `UnityEngine.Random` 대신 시드 기반 독립 RNG를 써야 하는지 설명할 수 있다
- [ ] fBm의 octaves/persistence/lacunarity가 각각 무엇을 바꾸는지 안다
- [ ] 셀룰러 오토마타로 동굴을 생성할 수 있다
- [ ] BSP 던전과 MST+루프 던전의 차이와 장단점을 안다
- [ ] 피셔-예이츠 셔플을 정확히 (off-by-one 없이) 작성할 수 있다
- [ ] 가중치 랜덤을 누적 배열 + 이진 탐색으로 구현할 수 있다
- [ ] 확률이 공정해도 유저가 불공정하다고 느끼는 이유와 천장/PRD/Bag 기법을 안다
- [ ] 생성 후 도달 가능성 검증의 필요성과 방법을 안다
