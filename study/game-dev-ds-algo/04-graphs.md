# 04. 그래프

> 그래프 표현 · 내비메시 · DAG · 위상 정렬 · 유니온 파인드 · MST

길찾기 알고리즘 자체는 [05. 길찾기](05-pathfinding.md)에서 다룹니다. 여기서는 **그래프라는 구조**와 길찾기 외 활용을 정리합니다.

---

## 1. 그래프 표현 방식

| 표현 | 메모리 | 인접 순회 | 간선 존재 확인 | 게임에서 |
|---|---|---|---|---|
| 인접 리스트 | O(V+E) | 빠름 | O(deg) | **대부분 이것** |
| 인접 행렬 | O(V²) | 느림 | O(1) | 노드 적고 밀집할 때 |
| 암시적 그래프 | O(1) | 계산으로 생성 | - | **격자 맵** |

### 암시적 격자 그래프 (게임에서 가장 흔함)
타일맵은 간선을 저장할 필요가 없습니다. 이웃은 좌표 계산으로 즉석에서 만듭니다.
```csharp
static readonly Vector2Int[] Dir4 = {
    new(0, 1), new(1, 0), new(0, -1), new(-1, 0)
};

IEnumerable<Vector2Int> Neighbors(Vector2Int p) {
    foreach (var d in Dir4) {
        var n = p + d;
        if (InBounds(n) && Walkable(n)) yield return n;
    }
}
```
> 8방향 이동을 허용할 때는 **대각선 코너 컷 방지**를 반드시 처리해야 합니다.
> 대각 이동 시 양옆 두 칸이 모두 통행 가능할 때만 허용하는 것이 일반적입니다.

## 2. 게임에서 쓰이는 그래프의 종류

| 형태 | 사용처 |
|---|---|
| **격자 그래프** | 타일 기반 이동, 로그라이크, SRPG, 퍼즐 |
| **웨이포인트 그래프** | NPC 순찰 경로, 커버 포인트 네트워크, 레이싱 라인 |
| **내비메시** | 걸을 수 있는 영역을 볼록 폴리곤으로 분할하고 인접 관계를 그래프로 |
| **DAG (비순환 방향 그래프)** | 스킬 트리, 퀘스트 선행 조건, 제작 레시피, 셰이더 그래프, 애니메이터 전이 |
| **대화 그래프** | 분기 대사, 선택지 |
| **소셜 그래프** | 친구 관계, 길드 |
| **포탈 그래프** | 실내 맵 방-문 연결 (가시성 판정용) |

## 3. 내비메시 (Navigation Mesh)

격자 대신 **걸을 수 있는 면 전체를 볼록 폴리곤으로 덮고**, 인접 폴리곤을 간선으로 연결한 그래프.

### 격자 대비 장점
- 노드 수가 압도적으로 적음 (넓은 평지 = 폴리곤 1장 vs 타일 수천 개)
- 에이전트가 격자에 갇히지 않아 이동이 자연스러움
- 높이/경사/점프 링크 표현이 쉬움

### 파이프라인
```
레벨 지오메트리
  → 복셀화(voxelize)
  → 걸을 수 있는 영역 추출 (경사/높이/반경 필터)
  → 영역 분할 및 폴리곤화
  → 내비메시 그래프
  → A* 로 폴리곤 경로 탐색
  → 퍼널 알고리즘으로 직선 경로 추출 (05번 문서)
```
Unity NavMesh, Recast/Detour(오픈소스 사실상 표준)가 이 방식입니다.

### 핵심 개념
- **Agent Radius** — 에이전트 크기만큼 벽에서 미리 깎아둠(erosion). 그래서 점으로 취급해도 벽에 안 낌
- **Area Cost** — 늪 3배, 도로 0.5배처럼 지형별 가중치
- **Off-Mesh Link** — 점프, 사다리, 문 등 불연속 이동
- **Carving** — 동적 장애물(NavMeshObstacle)이 메시를 실시간으로 도려냄

## 4. 위상 정렬 (Topological Sort)

DAG의 노드를 "선행 조건이 먼저 오도록" 일렬로 배치.

### 게임에서의 사용처
- **스킬 트리 / 테크 트리** — 해금 순서 검증, 순환 의존 탐지
- 퀘스트 선행 조건 체인
- 제작 레시피 의존성 (철광석 → 주괴 → 검)
- 애셋 로딩 / 초기화 순서
- 셰이더 그래프, 애니메이션 블렌드 그래프 평가 순서

### 순환 탐지가 실전 가치
기획 데이터에 "A는 B가 선행, B는 A가 선행" 같은 순환이 들어오면 게임이 영영 진행 불가가 됩니다.
**위상 정렬이 실패하면 순환이 존재**하므로 데이터 검증 도구로 그대로 쓸 수 있습니다.

```csharp
// Kahn 알고리즘: 진입 차수 0인 노드부터 제거
// 큐가 비었는데 남은 노드가 있으면 → 순환 존재
```

## 5. 유니온 파인드 (Disjoint Set Union)

원소들의 "같은 그룹인가"를 거의 O(1)에 판정. 경로 압축 + union by rank.

### 게임에서의 사용처
- **절차 생성 맵의 연결성 보장** — "모든 방이 서로 도달 가능한가"
- **Kruskal 기반 미로 생성** — 아직 연결 안 된 두 방 사이에만 벽을 허물어 순환 없는 완전 미로를 만듦
- 타일맵의 영역 라벨링 (섬 개수 세기 — 플러드 필로도 가능)
- 파티/길드 병합, 네트워크 클러스터

### 미로 생성 예시
```
1. 모든 벽을 랜덤 순서로 나열
2. 각 벽에 대해: 양쪽 칸이 Find로 다른 집합이면 → 벽 제거 + Union
3. 같은 집합이면 → 벽 유지 (순환 방지)
결과: 모든 칸이 연결되고 순환이 없는 완전 미로
→ 이후 벽 몇 개를 랜덤으로 더 허물면 루프가 생겨 게임플레이가 재미있어짐
```

## 6. 최소 신장 트리 (MST — Kruskal / Prim)

모든 노드를 최소 비용으로 연결하는 간선 집합.

### 게임에서의 사용처
- **던전 방 연결** — 방들을 들로네 삼각분할한 뒤 MST를 뽑아 최소 통로로 전부 연결, 그다음 제외된 간선 중 10~15%를 랜덤 복원해 **루프(순환 경로)** 를 만듦.
  MST만 쓰면 트리 구조라 "막다른 길 되돌아가기"만 반복돼 지루해집니다.
- 도로/파이프 네트워크 자동 배치 (시뮬레이션 게임)

---

## 7. 플러드 필 (Flood Fill)

BFS/DFS로 연결된 영역 전체를 채움.

### 게임에서의 사용처
- 페인트 툴의 채우기, 퍼즐 게임의 같은 색 블록 묶음 판정
- **맵 연결성 검사** — 절차 생성 후 고립된 영역을 찾아 제거하거나 통로로 연결
- 전장의 안개 영역 갱신
- 타일맵 영역 라벨링, 물 채우기 시뮬레이션
