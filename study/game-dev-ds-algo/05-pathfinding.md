# 05. 길찾기 (Pathfinding)

> BFS/DFS · 다익스트라 · A* · JPS · 플로우 필드 · 퍼널 알고리즘

게임 클라이언트 면접에서 가장 자주 나오는 주제입니다. **A\*는 반드시 직접 구현해본 경험이 있어야** 합니다.

---

## 1. BFS (너비 우선 탐색)

가중치가 없을 때의 최단 거리. 큐 사용.

### 게임에서의 사용처
- "이동력 3 이내 갈 수 있는 타일 하이라이트" (SRPG의 이동 범위 표시)
- 가장 가까운 목표 찾기 (가중치 동일할 때)
- 플러드 필, 연결성 검사
- 스킬 전파 (연쇄 번개가 인접 적으로 퍼짐)

```csharp
// 이동력 range 이내 타일 수집
var dist = new Dictionary<Vector2Int, int> { [start] = 0 };
var q = new Queue<Vector2Int>(); q.Enqueue(start);
while (q.Count > 0) {
    var cur = q.Dequeue();
    if (dist[cur] == range) continue;
    foreach (var n in Neighbors(cur)) {
        if (dist.ContainsKey(n)) continue;
        dist[n] = dist[cur] + 1;
        q.Enqueue(n);
    }
}
```

## 2. DFS (깊이 우선 탐색)

스택(또는 재귀) 사용. 최단 경로 보장 없음.

### 게임에서의 사용처
- **미로 생성** (재귀 백트래킹 — 8번 문서)
- 사이클 검출, 위상 정렬
- 씬 그래프 순회, 트리 직렬화
- 퍼즐 완전 탐색 + 백트래킹 (스도쿠, 넘버링)

---

## 3. 다익스트라 (Dijkstra)

가중치가 있을 때의 최단 경로. 우선순위 큐 사용. O((V+E) log V).

### 게임에서의 사용처
- 지형 코스트 반영 이동 (늪 3배, 도로 0.5배)
- **한 지점에서 모든 곳까지의 거리** 가 필요할 때 (위험도 맵, 영향력 맵의 거리 감쇠)
- 다중 출발점 다익스트라 → "가장 가까운 상점까지의 거리 맵"

### A*와의 관계
다익스트라는 **휴리스틱이 0인 A\***입니다. 목표가 하나면 A*가 훨씬 빠르고, 목표가 여러 개거나 전체 거리장이 필요하면 다익스트라가 맞습니다.

---

## 4. A* — 게임 길찾기의 표준

```
f(n) = g(n) + h(n)

g(n) = 시작점에서 n까지의 실제 누적 비용
h(n) = n에서 목표까지의 추정 비용 (휴리스틱)
```

**h가 실제 비용을 절대 넘지 않으면(admissible) 최적 경로를 보장**합니다.

### 휴리스틱 선택
| 이동 방식 | 휴리스틱 |
|---|---|
| 4방향 | 맨해튼 `|dx| + |dy|` |
| 8방향 (대각 비용 √2) | 옥타일 `max(dx,dy) + (√2-1)·min(dx,dy)` |
| 자유 이동 / 내비메시 | 유클리드 `sqrt(dx²+dy²)` |

### 구조
```csharp
openList  : 우선순위 큐 (f값 기준)   ← 03번 문서의 힙
closedSet : HashSet                   ← 02번 문서
cameFrom  : Dictionary<Node, Node>    ← 경로 복원용
gScore    : Dictionary<Node, float>
```

### 의사 코드
```
open.Push(start, f=h(start))
while open 비어있지 않음:
    cur = open.Pop()
    if cur == goal: return 경로복원(cameFrom, cur)
    if cur in closed: continue          // stale 항목 스킵
    closed.Add(cur)
    for n in Neighbors(cur):
        if n in closed: continue
        tentativeG = gScore[cur] + Cost(cur, n)
        if tentativeG < gScore.GetOrInf(n):
            cameFrom[n] = cur
            gScore[n]   = tentativeG
            open.Push(n, tentativeG + h(n))   // 중복 삽입 허용
```

### 실전 최적화
| 기법 | 효과 |
|---|---|
| **노드 풀링** | 매 탐색마다 노드 객체를 새로 할당하지 않음. GC 스파이크 방지 |
| **배열 기반 인덱싱** | 격자에서는 Dictionary 대신 `int idx = y * width + x` 로 배열 접근 |
| **세대 카운터** | closed 배열을 매번 Clear하지 않고 `searchId`를 비교해 초기화 생략 |
| **타임 슬라이싱** | 한 프레임 예산(예: 1ms)을 넘으면 중단하고 다음 프레임에 이어서 (코루틴/Job) |
| **경로 캐싱** | 동일 (출발, 목표) 쌍의 결과 재사용 |
| **계층적 A\*** | 맵을 청크로 나눠 상위 경로 먼저 구하고 청크 내부만 상세 탐색. 대형 맵 필수 |
| **h 가중치 (weighted A\*)** | `f = g + w·h (w>1)` → 최적성은 깨지지만 훨씬 빠름. 게임은 대개 허용 |

### 흔한 실수
- open list를 `List`로 두고 매번 선형 최솟값 탐색 → n이 커지면 급격히 느려짐
- 휴리스틱을 과대평가 → 엉뚱한 경로
- 경로를 그대로 이동에 쓰기 → 지그재그. **경로 스무딩/퍼널 필요**
- 매 프레임 전원이 길찾기 호출 → 요청 큐 + 프레임당 처리 개수 제한 필요

## 5. JPS (Jump Point Search)

**균일 비용 격자**에서 A*를 수 배~수십 배 가속. 대칭적으로 동일한 경로들을 가지치기하고, "점프 포인트"까지 한 번에 건너뜁니다.

### 조건과 한계
- 균일 격자 + 동일 이동 비용에서만 유효
- 지형별 가중치가 다르면 적용 불가
- 동적 장애물 변경 시 전처리 무효화

로그라이크, 타일 기반 RTS처럼 격자가 균일한 게임에 강력합니다.

---

## 6. 플로우 필드 / 벡터 필드

**목적지가 하나, 유닛이 수백~수천**일 때의 정답.

### 절차
```
1. 목표에서 시작하는 다익스트라/BFS로 맵 전체의 "목표까지 코스트" 맵 생성
2. 각 셀에서 가장 코스트가 낮은 이웃 방향을 저장 → 방향 벡터 필드
3. 모든 유닛은 자기가 선 셀의 화살표만 따라감 (개별 길찾기 0회)
```

### 비용 비교
```
유닛 500기 개별 A*     : 500회 탐색 / 목표 변경 시 전부 재계산
플로우 필드            : 1회 필드 생성 / 유닛 수와 무관
```

### 사용처
- RTS 대규모 유닛 이동, 타워디펜스 몹 웨이브
- 좀비 떼가 플레이어를 향해 몰려오는 게임
- 군중 시뮬레이션 (대피 경로)

### 주의점
- 맵이 크면 필드 생성 자체가 무거움 → 청크 단위 부분 갱신
- 목적지가 유닛마다 다르면 이점이 사라짐

## 7. 퍼널 알고리즘 (Funnel / String Pulling)

내비메시 A*가 반환하는 것은 **폴리곤의 나열**이지 경로가 아닙니다. 폴리곤 중심을 이으면 각지고 부자연스럽습니다.
퍼널 알고리즘은 통로(portal) 양 끝점으로 만든 시야 깔때기를 좁혀가며 **최단 직선 경로**를 뽑아냅니다.

```
폴리곤 중심 연결:  ┌─┐
                   │ └─┐        각지고 멀리 돌아감
퍼널 적용 후:      ╲___╲        코너를 스치는 최단 경로
```

### 관련 기법
- **경로 스무딩 (Raycast 기반)** — 경로 위 점 A에서 뒤쪽 점들로 레이를 쏴 막히지 않는 가장 먼 점까지 직선화. 격자 A* 결과에 흔히 적용
- **Catmull-Rom / 베지어 스플라인** — 곡선으로 부드럽게 (차량, 카메라)
- **Steering으로 후처리** — 경로를 목표점 시퀀스로 삼고 Arrive/Obstacle Avoidance 적용 (07번 문서)

---

## 8. 알고리즘 선택 가이드

| 상황 | 선택 |
|---|---|
| 가중치 없는 격자, 목표 1개 | BFS (또는 A*) |
| 지형 코스트 있음, 목표 1개, 유닛 소수 | **A\*** |
| 균일 격자, 성능 부족 | A* + **JPS** |
| 목표 1개, 유닛 수백 이상 | **플로우 필드** |
| 한 지점에서 모든 곳까지의 거리 필요 | 다익스트라 |
| 대형 오픈월드 | 계층적 A* / 내비메시 + 퍼널 |
| 3D 자유 지형 | **내비메시 + A\* + 퍼널** |
| 정적 맵, 임의 두 지점 질의가 매우 많음 | 전처리(Floyd-Warshall / Contraction Hierarchies) |
