# 07. 게임 AI

> FSM/HFSM · 행동 트리 · GOAP · 유틸리티 AI · 스티어링 · RVO · 영향력 맵 · 미니맥스/MCTS

## 1. FSM (유한 상태 기계)

가장 단순하고 가장 많이 쓰이는 구조. 상태 + 전이 조건.

```
Idle ──적 발견──> Chase ──사거리──> Attack
  ^                 │                  │
  └────적 놓침──────┘<───사거리 밖─────┘
```

### 게임에서의 사용처
- 몬스터 행동, NPC 일과
- **플레이어 캐릭터 상태** (Idle / Run / Jump / Dash / Hit / Dead) — 액션 게임에서 특히 중요
- 게임 흐름 (타이틀 → 로딩 → 인게임 → 결과)
- 애니메이션 상태 (Unity Animator가 곧 FSM)
- 네트워크 세션 상태

### 구현 형태
```csharp
interface IState {
    void Enter();
    void Update(float dt);
    void Exit();
}

class StateMachine {
    IState _cur;
    public void Change(IState next) {
        _cur?.Exit();
        _cur = next;
        _cur.Enter();
    }
    public void Tick(float dt) => _cur?.Update(dt);
}
```
`Enter/Exit`이 있는 것이 중요합니다. 진입 시 애니메이션 재생, 이탈 시 이펙트 정리 같은 처리를 한 곳에 모을 수 있습니다.

### 한계
- 상태가 n개면 전이가 최대 n² → **상태 폭발**
- "공격 중에도 피격 가능"처럼 직교하는 관심사를 표현하기 어려움

### 보완
- **HFSM (계층적 FSM)** — 상태를 그룹화. `전투` 슈퍼 상태 안에 `접근/공격/후퇴`. 공통 전이(사망)를 부모에 한 번만 정의
- **Pushdown Automata** — 상태를 스택으로 (01번 문서)
- **직교 상태** — 이동 FSM과 전투 FSM을 별도로 동시 운용

## 2. 행동 트리 (Behavior Tree)

→ 상세는 [03. 트리](03-trees.md#3-행동-트리-behavior-tree) 참조.

**요약**: Selector/Sequence/Decorator/Leaf 조합. 매 틱 `Success/Failure/Running` 반환.
FSM 대비 **상태 폭발 없음 · 서브트리 재사용 · 우선순위가 구조로 드러남**이 장점.

### FSM vs 행동 트리 선택 기준
| 상황 | 선택 |
|---|---|
| 상태 5개 이하, 전이가 명확 | FSM (더 단순함) |
| 플레이어 캐릭터 상태 | FSM (전이 제어가 중요) |
| 몬스터 AI, 행동이 계속 추가됨 | 행동 트리 |
| 기획자가 직접 조립해야 함 | 행동 트리 (비주얼 에디터 궁합) |

## 3. GOAP (Goal-Oriented Action Planning)

각 액션에 **전제조건(precondition)** 과 **효과(effect)** 를 선언하면, AI가 목표 상태에 도달하는 **행동 계획을 A*로 탐색**합니다.

```
목표: 적을 처치한다

액션 정의:
  총쏘기   : 전제 { 무기소지, 탄약있음, 시야확보 }  효과 { 적처치 }
  탄약줍기 : 전제 { 탄약근처 }                     효과 { 탄약있음 }
  이동     : 전제 { 경로있음 }                     효과 { 위치변경 }
  문열기   : 전제 { 열쇠소지 }                     효과 { 통로개방 }

→ 플래너가 자동 생성: 열쇠획득 → 문열기 → 탄약줍기 → 이동 → 총쏘기
```

### 특징
- **행동을 조립하는 규칙을 사람이 안 짜도 됨.** 액션만 추가하면 계획이 자동으로 달라짐
- 상황에 따라 다른 계획이 나와 **AI가 창발적으로 똑똑해 보임**
- F.E.A.R.(2005)가 유명한 사례. 소대 AI의 엄폐/우회가 이 방식

### 단점
- 탐색 비용이 큼 (액션이 많아지면 상태 공간 폭발)
- 디버깅과 예측이 어려움 — 기획자가 "왜 저렇게 행동하지?"를 추적하기 힘듦
- 액션 수 20~30개 규모까지가 현실적

## 4. 유틸리티 AI (Utility-Based AI)

각 행동에 **점수 함수**를 두고 매 틱 최고점 행동을 고릅니다.

```
공격 점수  = f(적 거리) × g(내 HP) × h(탄약)
후퇴 점수  = f(내 HP 낮음) × g(적 강함)
회복 점수  = f(HP 낮음) × g(포션 보유)
→ 매 틱 최댓값 선택
```

### 특징
- 조건문 분기가 아니라 **연속적인 곡선**으로 판단 → 자연스럽고 부드러운 행동 변화
- 곡선(커브 에디터)을 기획자가 조정하기 좋음
- 행동을 추가해도 기존 코드를 안 건드림 (점수 함수만 추가)

### 사용처
- 심즈류 시뮬레이션 (욕구 기반 행동 선택)
- 스포츠 게임 (패스/드리블/슛 선택)
- 전략 게임의 유닛 생산 우선순위
- 현대 상용 AI에서 **행동 트리와 하이브리드**로 자주 쓰임 (BT 노드 선택을 유틸리티 점수로)

### 단점
- 점수 스케일 튜닝이 까다로움
- "왜 이 행동을 골랐는가" 추적이 어려움 → 점수 로깅 도구 필수

## 5. 스티어링 비헤이비어 (Steering Behaviors)

Craig Reynolds의 조향 모델. 각 행동이 **가속도 벡터**를 내고, 이를 가중 합산해 최종 이동을 만듭니다.

| 행동 | 설명 |
|---|---|
| **Seek** | 목표를 향해 가속 |
| **Flee** | 목표에서 멀어짐 |
| **Arrive** | 목표에 가까워지면 감속해 정지 (Seek의 오버슈트 방지) |
| **Pursue / Evade** | 목표의 **미래 위치**를 예측해 추격/회피 |
| **Wander** | 자연스러운 배회 (랜덤 워크 + 관성) |
| **Obstacle Avoidance** | 전방 레이로 장애물 감지 후 회피 |
| **Path Following** | 경로를 따라가되 약간의 여유 폭 허용 |
| **Separation** | 이웃과 너무 가까우면 밀어냄 |
| **Alignment** | 이웃의 평균 진행 방향에 맞춤 |
| **Cohesion** | 이웃의 무게중심으로 모임 |

### 보이드 (Boids) = Separation + Alignment + Cohesion
이 세 규칙만으로 **새떼·물고기떼·군중**의 창발적 움직임이 나옵니다.

```csharp
Vector3 steer = seek      * 1.0f
              + separation* 1.5f    // 겹침 방지를 가장 세게
              + alignment * 0.8f
              + cohesion  * 0.6f
              + avoidance * 2.0f;   // 장애물 회피는 최우선
velocity = Vector3.ClampMagnitude(velocity + steer * dt, maxSpeed);
```

### 길찾기와의 역할 분담
```
A* / 플로우 필드 : 전역 경로 (어디로 갈지)
스티어링          : 지역 이동 (어떻게 갈지, 서로 안 부딪히게)
```
이 둘을 합치는 것이 실전 이동 시스템의 기본 구성입니다.

### 이웃 조회 최적화
Separation/Alignment/Cohesion은 전부 "주변 이웃"이 필요합니다. 전수 비교하면 O(n²) →
**공간 해시 그리드**(02번 문서)로 반드시 줄여야 합니다.

## 6. RVO / ORCA (상호 회피)

스티어링의 Separation만으로는 서로 마주 오는 유닛들이 **끼이거나 진동**합니다.
RVO(Reciprocal Velocity Obstacle)는 "상대도 절반만큼 피해준다"고 가정하고 **충돌하지 않는 속도 영역**을 계산합니다.

### 사용처
- RTS 유닛 군집 이동, MOBA 미니언
- 군중 시뮬레이션, 보행자 AI
- Unity NavMeshAgent의 `Obstacle Avoidance` 옵션이 이 계열

## 7. 영향력 맵 (Influence Map)

맵을 그리드로 나눠 각 셀에 **전략적 수치**를 기록하고 시간에 따라 전파/감쇠시킵니다.

```
아군 유닛 위치에 +값, 적 유닛 위치에 -값을 뿌리고
주변으로 거리 감쇠 전파 → 전선(0에 가까운 등고선)이 드러남
```

### 사용처
- "적 영향력이 높은 곳을 피해서 이동" (안전 경로 — A*의 코스트에 합산)
- 저격 포인트 / 엄폐물 평가
- RTS의 전선 판단, 공격 방향 결정
- 위험 지역 회피 (화염 장판 위를 안 밟는 AI)
- 자원 밀집도 기반 확장 위치 선정

### 구현 포인트
전체 그리드 갱신은 비싸므로 **저해상도 + 프레임 분산 갱신**이 일반적입니다.

## 8. 탐색 기반 AI (턴제·보드게임)

| 알고리즘 | 설명 / 사용처 |
|---|---|
| **미니맥스 + 알파베타 가지치기** | 2인 제로섬 완전 정보 게임. 체스, 오목, 체커. 알파베타로 탐색 노드를 대폭 줄임 |
| **반복 심화 (Iterative Deepening)** | 깊이 1,2,3...으로 반복 탐색. 시간 제한 내 최선 수를 항상 보유. 이전 결과로 무브 오더링 개선 |
| **트랜스포지션 테이블** | 동일 국면 재방문 시 캐시 재사용 (Zobrist 해싱) |
| **MCTS (몬테카를로 트리 탐색)** | 분기가 크거나 평가 함수 작성이 어려운 게임. 바둑, 카드 게임, 보드게임 AI. UCT로 탐색/활용 균형 |
| **난이도 조절** | 탐색 깊이 제한, 최선수 대신 n번째 수 선택, 의도적 실수 확률 — "이길 수 있지만 재미있게 진다" 튜닝 |

## 9. 기법 선택 가이드

| 상황 | 추천 |
|---|---|
| 플레이어 캐릭터 상태 | FSM (전이 제어 명확) |
| 단순 잡몹 | FSM |
| 보스, 복잡한 몬스터 | 행동 트리 |
| 기획자가 직접 AI 조립 | 행동 트리 + 비주얼 에디터 |
| 상황 적응형 계획이 핵심 재미 | GOAP |
| 욕구/점수 기반 자연스러운 선택 | 유틸리티 AI |
| 군중·떼 이동 | 스티어링/보이드 + 공간 해시 |
| RTS 대규모 유닛 | 플로우 필드 + RVO + 영향력 맵 |
| 턴제 보드게임 | 미니맥스+αβ 또는 MCTS |

## 체크리스트

- [ ] FSM을 Enter/Update/Exit 구조로 구현할 수 있다
- [ ] 상태 폭발 문제와 HFSM/Pushdown으로 완화하는 방법을 안다
- [ ] 행동 트리의 Running 반환값이 왜 중요한지 설명할 수 있다
- [ ] GOAP가 A*를 어디에 쓰는지 설명할 수 있다
- [ ] 보이드 3규칙을 구현하고 이웃 조회를 공간 해시로 최적화할 수 있다
- [ ] 전역 길찾기와 지역 스티어링의 역할 분담을 설명할 수 있다
- [ ] 영향력 맵을 A* 코스트에 반영해 "안전 경로"를 만드는 방법을 안다
