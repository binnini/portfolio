# 14. 실전 케이스 스터디

> 하나의 기능에 여러 자료구조·알고리즘이 어떻게 엮이는가 + 면접 대비 정리

개별 지식을 아는 것과 **조합해서 쓰는 것**은 다릅니다. 실제 기능 단위로 엮어봅니다.

## 케이스 1. 오픈월드에서 몬스터 300마리가 플레이어를 추격한다

| 단계 | 기법 | 문서 |
|---|---|---|
| 1. 플레이어 주변 몬스터만 추림 | **공간 해시 그리드** | [02](02-hash-and-set.md) |
| 2. 화면 밖 몬스터는 AI 갱신 주기 저하 | **프러스텀 컬링 + LOD + 타임 슬라이싱** | [10](10-rendering-visibility.md), [12](12-optimization-patterns.md) |
| 3. 목적지가 플레이어 하나 → 개별 A* 대신 공유 | **플로우 필드** | [05](05-pathfinding.md) |
| 4. 유닛끼리 겹치지 않게 | **스티어링 Separation + RVO** | [07](07-ai.md) |
| 5. 근접 시 타격 판정 | **AABB 브로드페이즈 → SAT 정밀 판정** | [06](06-collision-physics.md) |
| 6. 한 스윙에 중복 타격 방지 | **HashSet** | [02](02-hash-and-set.md) |
| 7. 피격 이펙트 / 데미지 텍스트 | **오브젝트 풀링** | [12](12-optimization-patterns.md) |
| 8. 출혈·둔화 지속시간 관리 | **우선순위 큐(힙)** | [03](03-trees.md) |
| 9. 상태이상 조합 판정 | **비트 플래그** | [02](02-hash-and-set.md) |
| 10. 드롭 아이템 결정 | **누적 확률 + 이진 탐색** | [08](08-procedural-generation.md), [09](09-sorting-searching.md) |
| 11. 멀티플레이라면 | **서버 권위 + 클라 예측 + 스냅샷 보간 + AoI** | [11](11-networking.md) |

### 핵심 통찰
"300마리 AI가 무겁다"의 해법은 **AI 알고리즘을 개선하는 것이 아니라, AI를 돌릴 대상을 줄이는 것**입니다.
공간 분할 → 컬링 → 갱신 주기 차등 → 공유 연산(플로우 필드) 순으로 대상을 깎고, 마지막에 남은 소수에만 정밀 처리를 합니다.

## 케이스 2. 로그라이크 던전 한 층을 생성한다

```
1. BSP 분할 또는 방 랜덤 배치 + 물리 밀어내기          → 08
2. 방 중심들로 들로네 삼각분할                          → 13
3. MST 추출로 최소 연결 확보 (유니온 파인드)            → 04
4. 제외된 간선 중 10~15% 랜덤 복원 → 루프 생성          → 04
5. 통로를 브레젠험/L자로 그림                           → 10
6. 셀룰러 오토마타로 동굴 구역 추가                     → 08
7. 플러드 필로 도달 불가 영역 검출 및 제거              → 04
8. 시작점에서 BFS로 각 방의 거리 계산                   → 05
9. 거리 기반으로 난이도/보상 배치 (먼 방일수록 강함)    → 05
10. 열쇠-문 배치는 위상 정렬로 도달 가능성 검증         → 04
11. 포아송 디스크로 장식물/아이템 산포                  → 08
12. 전체를 고정 시드 RNG로 → 같은 시드 = 같은 층        → 08
```

### 핵심 통찰
**생성(1~6)보다 검증(7~10)이 실무 난이도**입니다. "열쇠가 그 열쇠로 여는 문 뒤에 있는" 버그를 막는 게 도달성 검증입니다.

## 케이스 3. 격투 게임의 롤백 넷코드

```
입력 수집    → 버튼 상태를 비트 패킹 (1바이트)            → 02, 13
입력 히스토리 → 링 버퍼 (최근 10프레임)                    → 01
커맨드 판정   → 덱/링 버퍼에 저장된 최근 입력을 뒤에서 매칭 → 01
상태 저장    → POD 구조체 스냅샷을 링 버퍼에               → 01, 11
예측         → 상대 입력 미도착 시 직전 입력 반복 가정     → 11
롤백         → 불일치 프레임으로 되감고 고속 재시뮬        → 11
결정론       → 고정소수점 + 고정 타임스텝 + 시드 RNG       → 13
판정         → 히트박스/허트박스 AABB 또는 OBB(SAT)        → 06
검증         → 주기적 체크섬 비교로 데스싱크 탐지          → 13
```

### 핵심 통찰
롤백의 난이도는 네트워크가 아니라 **결정론과 상태 직렬화 설계**에 있습니다. 게임 상태를 처음부터 "빠르게 복사 가능한 POD"로 설계해야 나중에 얹을 수 있습니다.

## 케이스 4. MMO 서버가 1000명 접속을 처리한다

```
관심 영역(AoI)  : 그리드/쿼드트리로 시야 내 대상만 동기화     → 02, 03, 11
브로드캐스트    : 우선순위 큐로 대역폭 예산 내 중요도 순 전송 → 03, 11
타이머          : 타임 휠로 수만 개 쿨다운/버프 O(1) 관리      → 12
길찾기          : 요청 큐 + 계층적 A* + 경로 캐시              → 05, 12
아이템/스킬 DB  : Dictionary 인덱싱, 정수 ID 인터닝            → 02, 13
랭킹            : Skip List(Redis Sorted Set)                  → 03
채팅 필터       : Aho-Corasick + 정규화                        → 13
패킷            : 델타 압축 + 양자화 + 비트 패킹                → 11
검증            : 서버 권위 — 이동 속도/사거리/쿨다운 전부 검증 → 11
```

## 케이스 5. 인벤토리 / UI 시스템

```
슬롯 저장      : 배열 (고정 크기) 또는 Dictionary (아이템ID → 개수)   → 01, 02
아이템 데이터  : ScriptableObject + Dictionary 인덱스                  → 02
정렬           : 등급/이름/획득순 정렬 + 더티 플래그로 재정렬 최소화   → 09, 12
검색/자동완성  : Trie                                                  → 13
화면 전환      : UI 스택 (Push/Pop)                                    → 01
아이템 슬롯    : 오브젝트 풀 (스크롤 리스트의 가상화)                  → 12
등장 연출      : 이징 (EaseOutBack)                                    → 09
필터           : 비트 플래그 (무기|방어구|소비)                        → 02
```

### 스크롤 리스트 가상화
아이템 1000개를 전부 생성하지 않고 **화면에 보이는 10개 + 여유분만 풀에서 대여**해 재활용합니다.
Unity UI에서 인벤토리가 버벅이는 문제의 표준 해법입니다.

## 면접 대비 — 질문별 대응 정리

| 예상 질문 | 답변에 넣을 것 |
|---|---|
| "A*를 설명해보세요" | f=g+h, 휴리스틱 admissible 조건, open=힙 / closed=HashSet, 경로 복원, **실제 최적화 경험**(노드 풀링, 타임 슬라이싱) |
| "길찾기가 무거운데 어떻게 최적화하죠?" | 요청 큐 + 프레임 예산, 경로 캐시, 계층적 A*, **유닛이 많으면 플로우 필드로 전환** |
| "Dictionary와 List 중 뭘 쓰겠습니까?" | 접근 패턴(조회 위주 vs 순회 위주), n의 크기, **캐시 지역성과 GC** |
| "몬스터 AI를 어떻게 구성하나요?" | 규모에 따라 FSM vs 행동 트리, Enter/Exit 설계, **갱신 주기 차등** |
| "최적화 경험을 말해보세요" | 측정 → 원인 → 조치 → **수치로 검증**. 프로파일러 스크린샷 수준의 구체성 |
| "GC 스파이크를 어떻게 잡나요?" | NonAlloc API, 풀링, 문자열/LINQ 제거, 컴포넌트 캐시 |
| "충돌 처리를 직접 짠다면?" | 브로드페이즈/내로우페이즈 분리, AABB → SAT, 공간 해시 |
| "멀티플레이 경험이 있나요?" | 없어도 예측/보정/보간 개념은 설명할 수 있어야 함 |

### 답변 구성 템플릿
```
1. 문제 상황     — "몬스터 200마리에서 프레임이 30fps로 떨어졌습니다"
2. 원인 분석     — "프로파일러로 보니 개별 A* 호출이 프레임의 40%였습니다"
3. 선택과 근거   — "목적지가 하나라 플로우 필드로 바꿨습니다. 유닛 수와 무관해지므로"
4. 결과 (수치)   — "길찾기 비용이 40% → 3%로 줄고 60fps를 유지했습니다"
5. 남은 한계     — "목적지가 여러 개인 상황에는 이 방식이 안 맞아서 하이브리드로..."
```
**4번의 수치와 5번의 한계 인식**이 지원자를 구분합니다.

## 학습 로드맵

### 1단계 — 손으로 구현 (각 1~2일)
- [ ] A* (격자, 우선순위 큐 직접 구현)
- [ ] 오브젝트 풀
- [ ] FSM (Enter/Update/Exit)
- [ ] 공간 해시 그리드
- [ ] 링 버퍼

### 2단계 — 작은 프로젝트로 통합 (각 1주)
- [ ] 타일 기반 로그라이크: 절차 생성 + A* + 시야 계산
- [ ] 보이드 시뮬레이터: 스티어링 + 공간 해시 (유닛 500개로 프로파일링까지)
- [ ] 간단한 타워디펜스: 플로우 필드 + 풀링 + 웨이브 스케줄러

### 3단계 — 심화 (선택)
- [ ] 행동 트리 프레임워크 자작
- [ ] 결정론 시뮬레이션 + 리플레이 저장/재생
- [ ] 2인 로컬 롤백 넷코드 프로토타입
- [ ] DOTS/Job System으로 1단계 결과물 재작성 후 성능 비교

### 측정 습관
무엇을 만들든 **"몇 개까지 버티는지"** 를 재고 기록해두세요.
"보이드 500개에서 60fps, 공간 해시 적용 전에는 120개였다" 같은 수치가 포트폴리오에서 가장 강력합니다.
