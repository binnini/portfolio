## 학습 우선순위

Unity 클라이언트 기준, 투자 대비 효율 순서입니다.

### Tier 1 — 필수 (모르면 실무가 막힘)
- `List<T>` / `Dictionary` / `HashSet` / 스택 / 큐 — Big-O + **GC 동작**(struct vs class, boxing, 용량 재할당)까지
- **A\***, BFS/DFS, 우선순위 큐 — 길찾기는 면접 단골
- **오브젝트 풀링**, 더티 플래그, 타임 슬라이싱 — "최적화 경험" 질문의 핵심
- **FSM / 행동 트리** — 플레이어 상태, 몬스터 AI

### Tier 2 — 중요 (규모가 커지면 반드시 필요)
- 공간 분할(그리드 / 쿼드트리 / 옥트리), 프러스텀 컬링
- 링 버퍼, 이벤트 큐, 비트 플래그
- 보간(Lerp / Slerp / 베지어), 이징, 스플라인

### Tier 3 — 가산점 (장르·포지션에 따라 강력한 차별점)
- 절차적 생성 (노이즈, 셀룰러 오토마타, WFC)
- 넷코드 (예측 · 보정 · 롤백)
- GJK/SAT, ECS Sparse Set, DOTS

## 이 노트를 쓰는 법

1. **먼저 문제부터 본다.** "몬스터 300마리 추격"처럼 상황을 정하고, 어떤 구조가 왜 필요한지 역으로 찾는다.
2. **복잡도보다 상수와 캐시.** 게임은 n이 작고(수백~수천) 프레임 예산이 빡빡해서, O(n log n)이 O(n)을 이기는 경우가 흔하다. 배열 선형 탐색이 트리보다 빠른 구간이 실제로 존재한다.
3. **GC를 항상 의식한다.** Unity에서는 알고리즘보다 프레임당 할당이 스파이크의 주원인인 경우가 많다.
4. **직접 구현해보고, 실무에서는 엔진 기능을 쓴다.** A*를 손으로 짜보되 프로덕션에서는 NavMesh를 쓰는 식.
