# 10. 렌더링 · 가시성

> 프러스텀 컬링 · 오클루전 컬링 · 포탈 · LOD · 배칭 · 브레젠험 · 시야 계산

렌더링 최적화의 제1원칙: **"가장 빠른 드로우콜은 그리지 않는 드로우콜이다."**

---

## 1. 프러스텀 컬링

카메라 절두체(6개 평면) 밖의 오브젝트를 제외.

```
바운딩 구 vs 평면 6개:
  각 평면에 대해 signed distance < -radius 이면 → 완전히 밖 → 제외
```

### 가속
- 오브젝트가 수천 개면 전수 검사도 부담 → **쿼드트리/옥트리/BVH**로 계층 컬링.
  부모 노드가 절두체 밖이면 **자손 전체를 한 번에 제외**
- SIMD로 여러 바운딩을 동시에 검사

Unity는 자동으로 수행하지만, **왜 큰 오브젝트 하나보다 적당히 쪼갠 여러 개가 유리한지**(부분 컬링 가능)를 이해해야 합니다.

---

## 2. 오클루전 컬링

절두체 안에 있지만 **다른 물체에 가려진** 것을 제외.

| 기법 | 설명 |
|---|---|
| **사전 계산 (PVS)** | 맵을 셀로 나눠 "이 셀에서 보이는 셀 목록"을 오프라인 계산. 정적 실내 맵에 강력 (Unity Occlusion Culling) |
| **하드웨어 오클루전 쿼리** | GPU에 "이 바운딩 박스가 픽셀을 남기나?" 질의. 지연(latency) 문제 |
| **Hi-Z / HZB** | 깊이 버퍼 밉맵을 만들어 바운딩 박스를 계층적으로 테스트. 현대적 GPU 컬링 |
| **소프트웨어 오클루전** | CPU에서 저해상도 깊이 버퍼를 래스터화해 테스트 |

### 트레이드오프
오클루전 컬링 자체에도 비용이 듭니다. **넓은 실외 맵에서는 손해**인 경우가 흔하고, 벽이 많은 실내에서 이득이 큽니다.

## 3. 포탈 컬링

실내 맵을 방(cell)과 문(portal)의 그래프로 만들고, 카메라가 있는 방에서 보이는 포탈을 통해서만 인접 방을 재귀 탐색.

```
현재 방 렌더
  → 화면에 보이는 포탈이 있으면
     → 그 포탈 사각형으로 절두체를 좁혀서 옆 방 렌더
        → 재귀
```
실내 FPS, 우주선/던전 같은 방-복도 구조에 매우 효과적입니다.

## 4. LOD (Level of Detail)

| 종류 | 설명 |
|---|---|
| **메시 LOD** | 거리별로 저폴리 메시 교체 |
| **텍스처 밉맵** | 거리별 저해상도 텍스처 (캐시 효율 + 앨리어싱 방지) |
| **임포스터 / 빌보드** | 아주 먼 물체를 2D 판때기로. 숲 렌더링의 표준 |
| **HLOD** | 여러 오브젝트를 하나의 저폴리 메시로 병합 (드로우콜까지 감소) |
| **터레인 쿼드트리 LOD** | 거리별 지형 패치 해상도 조절, 경계 크랙 처리 필요 |
| **애니메이션 LOD** | 먼 캐릭터는 본 갱신 주기를 낮추거나 생략 |
| **AI / 물리 LOD** | 먼 곳의 AI는 4프레임에 1회 갱신, 물리는 단순화 |

**LOD는 렌더링만의 개념이 아닙니다.** AI·물리·사운드에도 같은 사고를 적용하는 것이 대규모 씬 최적화의 핵심입니다.

## 5. 배칭 / 인스턴싱

| 기법 | 설명 |
|---|---|
| **Static Batching** | 정적 오브젝트의 메시를 미리 병합. 메모리 증가 대신 드로우콜 감소 |
| **Dynamic Batching** | 작은 메시를 런타임에 CPU에서 병합. 정점 수 제한 있음 |
| **GPU Instancing** | 같은 메시+머티리얼을 인스턴스 데이터만 바꿔 한 번에 그림. 풀, 나무, 총알, 몬스터 떼 |
| **SRP Batcher** | 셰이더가 같으면 머티리얼이 달라도 상수 버퍼 갱신을 최소화 |
| **텍스처 아틀라스** | 여러 텍스처를 한 장에 합쳐 배칭 조건을 만족시킴. UI 스프라이트 아틀라스가 대표적 |

배칭의 전제는 **상태 변경 최소화**이고, 그걸 달성하는 수단이 09번 문서의 **정렬 키 설계**입니다.

## 6. 브레젠험 직선 알고리즘

정수 연산만으로 격자 위의 직선을 그립니다.

### 게임에서의 사용처
- **타일 기반 시야 판정 (Line of Sight)** — 두 타일 사이에 벽이 있는지
- 로그라이크의 투사체 경로, 사격 가능 판정
- 타일맵 위 레이 추적, 전장의 안개 갱신
- 미니맵 선 그리기, 절차 생성 통로 그리기

```
(x0,y0) 에서 (x1,y1) 까지 격자 칸을 순회하며
벽 타일을 만나면 즉시 false → 시야 차단
```

## 7. 시야 / FOV 계산

### 재귀적 그림자 캐스팅 (Recursive Shadowcasting)
로그라이크 시야 계산의 표준. 8개의 옥탄트로 나눠 각도 구간(slope)을 좁혀가며 가려진 영역을 배제합니다.
브레젠험을 전 방향으로 쏘는 방식보다 정확하고 빠릅니다.

### 사용처
- 로그라이크 시야, 전장의 안개(Fog of War)
- RTS 유닛 시야 범위
- 스텔스 게임의 경비병 시야 콘

### 시야 콘 판정 (3D 액션의 실전 패턴)
```csharp
Vector3 toTarget = target.position - transform.position;
if (toTarget.sqrMagnitude > sightRange * sightRange) return false;   // 1. 거리
if (Vector3.Dot(transform.forward, toTarget.normalized)
        < Mathf.Cos(fovAngle * 0.5f * Mathf.Deg2Rad)) return false;  // 2. 각도
if (Physics.Linecast(eye.position, target.position, obstacleMask))
        return false;                                                 // 3. 차폐
return true;
```
**싼 판정부터 순서대로** 거는 것이 포인트입니다. 거리 → 각도 → 레이캐스트 순으로,
비싼 레이캐스트는 앞의 두 관문을 통과한 소수에게만 수행합니다.

## 8. 기타 렌더링 관련 알고리즘

| 기법 | 설명 |
|---|---|
| **Z-버퍼 / 깊이 테스트** | 픽셀 단위 가시성. 화가 알고리즘을 대체 |
| **Early-Z / Depth Prepass** | 깊이만 먼저 그려 픽셀 셰이더 실행을 줄임 |
| **화가 알고리즘** | 반투명 오브젝트에는 여전히 필요 (뒤→앞 정렬) |
| **빈 패킹 (Bin Packing)** | 텍스처 아틀라스 자동 생성, 라이트맵 UV 배치 |
| **컬링 + 정렬 파이프라인** | 컬링 → 정렬 키 생성 → 기수 정렬 → 드로우콜 제출 |
