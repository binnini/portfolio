## 1. 게임에서 정렬이 필요한 순간

| 상황 | 설명 |
|---|---|
| **반투명 오브젝트 렌더 순서** | 알파 블렌딩은 뒤→앞 순서가 필수 (화가 알고리즘) |
| **드로우콜 배칭** | 머티리얼/셰이더/텍스처가 같은 것끼리 모아 상태 변경 최소화 |

## 2. 삽입 정렬 — "거의 정렬된" 데이터의 강자

일반적으로 O(n²)지만, **이미 거의 정렬된 데이터에서는 O(n)에 가깝게** 동작합니다.

### 왜 게임에서 중요한가
게임 데이터는 **프레임 간 변화가 작습니다**. 카메라가 1프레임에 크게 안 움직이므로 깊이 정렬 순서도 거의 그대로입니다.
```
프레임 t   : [A, B, C, D, E]
프레임 t+1 : [A, C, B, D, E]   ← 두 개만 바뀜
→ 매번 O(n log n) 퀵/머지 정렬보다 삽입 정렬이 실측으로 더 빠름
```

### 사용처
- Sweep and Prune의 축 정렬 (물리 엔진의 고전적 최적화)
- 프레임 간 일관성이 있는 렌더 순서
- 작은 배열(n < 32) — 대부분의 하이브리드 정렬이 이 구간에서 삽입 정렬로 전환

## 3. 기수 정렬 (Radix Sort)

비교 없이 자릿수 기준으로 버킷 분배. 정수 키에 O(n).

### 렌더 큐 정렬 — 실전 활용
드로우콜 정렬 키를 하나의 정수에 비트 패킹합니다.
```
[ 63..60 ] 레이어 (불투명/반투명/UI)
[ 59..44 ] 셰이더 ID
[ 43..28 ] 머티리얼 ID
[ 27..0  ] 깊이 (불투명은 앞→뒤, 반투명은 뒤→앞으로 반전)

→ 64bit 정수 하나를 기수 정렬 → 상태 변경 최소 + 올바른 블렌딩 순서
```
현대 렌더러(Unity SRP 포함)가 쓰는 표준 기법입니다. "정렬 키 설계"라는 개념 자체를 알아두면 좋습니다.

## 4. 이진 탐색

정렬된 배열에서 O(log n) 조회. 게임에서 의외로 자주 씁니다.

### 사용처
| 상황 | 설명 |
|---|---|
| **애니메이션 키프레임 구간 찾기** | 현재 시간이 어느 두 키 사이인지 → 보간 |
| **애니메이션 커브 / 그라디언트 평가** | 동일 |
| **가중치 랜덤 샘플링** | 누적 분포 배열에서 난수 위치 찾기 (08번 문서) |
| **레벨 테이블 조회** | 경험치 → 레벨 |
| **랭킹 구간 조회** | 내 점수의 순위 |
| **LOD 거리 임계값** | 거리 → LOD 단계 |

### `lowerBound` / `upperBound`
구간 질의에는 단순 "찾기"가 아니라 경계 탐색이 필요합니다. 직접 구현할 수 있어야 합니다.
```csharp
// arr[i] >= target 인 첫 인덱스
int LowerBound(float[] arr, float target) {
    int lo = 0, hi = arr.Length;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;   // 오버플로 방지
        if (arr[mid] < target) lo = mid + 1;
        else hi = mid;
    }
    return lo;
}
```

### 애니메이션 키프레임 최적화
매 프레임 이진 탐색하는 대신 **직전 인덱스를 캐시**해두고 거기서 선형 전진하는 방식이 더 빠릅니다
(시간은 대개 단조 증가하므로). 재생 위치가 점프할 때만 이진 탐색으로 폴백합니다.

## 5. Top-K — 전체 정렬을 피하기

"1만 명 중 상위 100명"에 전체 정렬은 낭비입니다.

| 방법 | 복잡도 |
|---|---|
| 전체 정렬 | O(n log n) |
| **크기 K 최소 힙 유지** | O(n log K) |
| Quickselect (nth_element) | 평균 O(n) |

### 사용처
- 랭킹 상위 N명
- "가장 가까운 적 5명" (거리 기준 Top-K)
- 파티클/이펙트 예산 초과 시 중요도 상위만 렌더
- AI의 위협도 상위 대상 선정

## 6. 보간 (Interpolation)

정렬·탐색과 함께 매일 쓰는 수치 도구입니다.

### 기본
```csharp
Lerp(a, b, t)   = a + (b - a) * t         // 선형
Slerp(qa, qb, t)                          // 구면 선형 — 회전에는 반드시 이것
InverseLerp(a, b, v) = (v - a) / (b - a)  // 값 → 0~1 정규화 (HP바 등)
SmoothStep(t) = t * t * (3 - 2 * t)       // 부드러운 가감속
```

### 프레임 독립 감쇠 — 흔한 버그
```csharp
// 나쁨: 프레임레이트에 따라 결과가 달라짐
pos = Vector3.Lerp(pos, target, 0.1f);

// 좋음: dt 보정
pos = Vector3.Lerp(pos, target, 1f - Mathf.Exp(-rate * Time.deltaTime));
```
`Lerp(a, b, speed * dt)`도 흔히 쓰이지만 엄밀하게는 프레임 독립이 아닙니다.
60fps와 144fps에서 카메라 추적 속도가 달라지는 버그의 전형적 원인입니다.

### 스플라인
| 종류 | 특징 / 사용처 |
|---|---|
| **베지어 (Quadratic/Cubic)** | 제어점으로 곡선. 투사체 궤적, UI 연출, 경로 |
| **Catmull-Rom** | **모든 제어점을 통과**. 카메라 경로, 레이싱 라인, 경로 스무딩에 가장 적합 |
| **Hermite** | 위치 + 접선 지정. 애니메이션 커브 내부 |
| **B-Spline** | 점을 통과하지 않지만 매우 매끄러움 |

### 이징 (Easing)
UI/연출의 체감 품질을 좌우합니다.
```
EaseOutQuad   : 빠르게 시작해 부드럽게 정지  ← UI 등장에 가장 무난
EaseOutBack   : 살짝 지나갔다 돌아옴         ← 팝업 등장, 통통 튀는 느낌
EaseOutElastic: 탄성 진동                    ← 강조 연출
EaseInOutCubic: 가속 후 감속                 ← 카메라 이동
```

### 게임 로직에서의 곡선
- 데미지 감쇠 곡선 (거리에 따른 폭발 데미지)
- 경험치 곡선, 스탯 성장 곡선
- 난이도 곡선 (웨이브별 몬스터 강도)
- 카메라 FOV / 흔들림 감쇠
